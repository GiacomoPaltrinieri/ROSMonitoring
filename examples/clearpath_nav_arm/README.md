# Clearpath Nav2 + MoveIt ROSMonitoring case study

This case study uses the ROS 2 Jazzy Clearpath A200 simulation with a Kinova
Gen3 Lite arm, MoveIt 2, Nav2, `ros2_control`, and Gazebo Harmonic.
The robot configuration is defined in [`clearpath/robot.yaml`](clearpath/robot.yaml);
the remaining robot description and launch files are generated by Clearpath.

## Properties

- **P1 — safe pose before navigation:** reject a Nav2 goal unless measured
  joint positions show that the arm is in `stow` or in the predefined `carry`
  pose used to transport a box.
- **P2 — no arm execution during navigation:** reject a low-level arm trajectory
  from the Nav2 goal request until Nav2 publishes a terminal status.
- **P3 — keep the load secured:** reject a request to open the gripper while
  Nav2 is navigating.

## One-time setup

Install the required packages:

```bash
sudo apt update
sudo apt install \
  ros-jazzy-clearpath-simulator \
  ros-jazzy-clearpath-nav2-demos \
  ros-jazzy-clearpath-manipulators \
  ros-jazzy-kortex-description \
  ros-jazzy-rmw-cyclonedds-cpp
```

From the ROSMonitoring repository root, enter the case-study directory and run
the setup:

```bash
cd examples/clearpath_nav_arm
./scripts/bootstrap.sh
```

## Experimental Scenario 1 - Navigation and arm coordination

The arm moves to `STOW` and the robot starts a five-metre navigation. During
navigation, the scenario requests an arm movement. The baseline executes it;
ROSMonitoring rejects it according to P2.

```bash
./scripts/run_case_study.sh baseline
./scripts/run_case_study.sh monitored
```

## Experimental Scenario 2 - BOX Transport

The robot picks up a box, moves the arm to `CARRY`, and starts a five-metre
navigation. After two metres, the scenario requests the gripper to open. The
baseline drops the box; ROSMonitoring rejects the request according to P3.

```bash
./scripts/run_box_test.sh baseline
./scripts/run_box_test.sh monitored
```
